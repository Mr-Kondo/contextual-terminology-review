# 効果測定の手順（人による測定）

Skillの効果は、**受け手の理解が良くなるか**で測る。機械検査や別モデルの判定は、効果の証拠にならない。このページは、人（同僚など）の参加を得て測る手順と、その前にこちらで行った予備試験の位置づけをまとめる。

## 0. 予備試験（模擬の受け手）の位置づけ

[docs/evidence/effect-pilot.md](evidence/effect-pilot.md) は、別のAIモデルを受け手にして、同じ手順の仕組み（単一版の配布・版を伏せた割付・自動採点）が通ることと、修正案が理解を損なっていないかの目安を見たもの。**人の受け手の代わりにならない。** 項目と正解の作成者はSkillの設計者と同じAIで、独立していない。

初見の入力から、Skillありと素のモデルの最終出力を比べた測定は [E2E評価](E2E-EVAL.md)。発動精度は [TRIGGER-EVAL](TRIGGER-EVAL.md)。

## 1. 測ること（事前に固定する）

| 指標 | 内容 | 判断基準 |
|---|---|---|
| 理解の正答率（主） | 同じ内容を、**元の言い方**と**Skillの修正案**のどちらか一方だけ見た受け手が、資料から作った選択式の質問に正しく答えた割合 | 修正案の正答率が元より 0.15 以上高い。質問ごとの差の符号が、改善 > 悪化 |
| 害の疑い | 修正案を見た受け手の正答率が、元より 0.25 以上低い質問 | 1つでもあれば原因を調べる（Issue化） |
| 『分からない』の割合 | 文だけでは判断できないと答えた割合 | 修正案で減ることが期待。増えるなら理由を調べる |
| 本人の意図の保持 | 修正案が、本人の意図と確認済み事実を保っているか（本人が判断） | `feedback add --intent kept/changed` |
| 使われたか | 提案をそのまま・修正して使ったか | `feedback add --usage as_is/edited/unused` |
| 手間 | 設定・記録・根拠確認・比較・練習にかかった分 | `feedback time` |

基準は、予備試験で実行前に固定したものを踏襲した。実際の人数・課題数に合わせて見直す場合も、**結果を見る前に**決める。

## 2. 設計

- **項目**: 実際の業務で起きた、曖昧さや誤用が疑われる言い方（10〜20件）。元の言い方・Skillの修正案・資料（確認済みの事実）の3つを用意する
- **質問**: 資料から作る選択式（各項目1〜3問）。選択肢に『文だけでは分からない』を含める。**正解は資料から付け、修正案の内容に依存させない**。質問は、修正案を作った人と別の人が作るのが望ましい
- **対照**: 修正案が無い（適合）項目を1〜2件、両方の版を同一の文にして入れる。判定のばらつきの目安になる
- **配布**: 受け手一人に、一つの項目の**どちらか一つの版だけ**を渡す（`ctr.py comprehension prepare` が割付し、`check` が確認する）。版の名前・正解・根拠は渡さない。受け手には資料を見せない
- **人数**: 項目あたり、各版10人以上が目安（予備試験の8人では、質問ごとの正答率の幅が大きかった）。同じ人が両方の版を見ないようにする
- **採点**: 選択式は自動。自由記述を使うときは人が採点し、理由を残す（`--scores`）
- **除外**: 別の版を先に読んだ回答は除外し、件数を示す

## 3. 手順

```bash
# 項目ファイルを用意（tools/data/effect-pilot-items.json が書式の見本）
python3 skill/contextual-terminology-review/scripts/ctr.py comprehension prepare --items my-items.json --readers a,b,c,... --out ~/ctr-data/effect-run --seed 1
python3 skill/contextual-terminology-review/scripts/ctr.py comprehension check --dir ~/ctr-data/effect-run/readers
# readers/reader-NNN/tasks.json を受け手に渡す。organizer/ は渡さない（受け手と、Skillを動かすAgentから見えない場所に置く）
# 回答を集めたら:
python3 skill/contextual-terminology-review/scripts/ctr.py comprehension score --organizer ~/ctr-data/effect-run/organizer/organizer.json --responses responses.json
```

模擬の受け手（AI）で同じ手順を試すときは `tools/effect_pilot.py`（`prepare` で受け手ごとの `prompt.txt` を作り、別々のセッションで1回ずつ実行し、`score` で集計する）。

## 4. 注意

- 受け手に見せる文面は、機密・個人情報を含めないよう、実施前に確認する。参加は任意で、結果は個人の評価に使わない
- 『効果あり』と言えるのは、人の受け手で基準を満たしたときだけ。予備試験の結果は『手順が通った』『害の疑いは見つからなかった（または見つかった）』にとどまる
- 件数が少ないうちは、区間が広い。点推定だけで結論を出さない
- Skillを使わない場合（元の言い方のまま）との比較であって、他の推敲手段との優劣は示さない
