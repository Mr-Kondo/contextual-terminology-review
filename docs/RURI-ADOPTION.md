# Ruri検索の採否判断（2026-10-17、検証の途中結果）

結論は「**この証拠の範囲では、310mなら任意の補助として使える可能性がある。70mは基準に届かなかった**」。**決定（利用者、2026-10-17）: 既定モデルを `cl-nagoya/ruri-v3-310m`（revision `18b60fb8…`、既定のときだけ版を固定）にした。** 実データでの確認は残っており、Ruriは引き続き任意の補助である。70mは `--model cl-nagoya/ruri-v3-70m` で指定できる。

## 何を比べたか

用語の一致検索では見つからない言い方（表記ゆれ・言い換え）を、用語集から拾えるか。

- 比較対象: 一致検索（現行）／文字2-gram（標準ライブラリのみ。依存なしの代替案）／Ruri v3 70m（現行の既定）／Ruri v3 310m／一致＋補助（一致を先頭に、閾値を超えた補助の結果で埋める）
- 課題セット: [tools/data/ruri-adoption-set.json](../tools/data/ruri-adoption-set.json)。架空の用語集40語、課題80件（そのまま含む16・表記ゆれ20・言い換え24・無関係20）。偶数番がdev（閾値の決定だけに使用）、奇数番がtest（報告の主）
- 採点: 正解のどれかが上位3件に入れば命中。無関係な文には『何も返さない』が正解
- 閾値: devの無関係課題の1位得点の最大値。これを**超えた**結果だけを返す。positive側の成績は閾値の決定に使っていない
- 採否基準（実行前に固定。`tools/bench_ruri_adoption.py` の冒頭）: testの表記ゆれ＋言い換え（n=22）で、Ruriの閾値つきhit@3が**0.60以上**、かつ文字2-gramより**0.15以上高く**、testの無関係課題の誤検出が**0.20以下**

- 17/22（0.77）の95%区間（Wilson）は0.57〜0.90。基準Aの0.60は区間の下限を下回るため、基準は点推定で満たしただけ。
- 一致検索の無関係課題の誤検出は報告の表には出していない（閾値の概念が無いため）。課題セットの検査（`tests/test_ruri_bench_set.py`）で、無関係な20件に一致が無いことは確認している。一方、`キャッシュ・フロー` が `キャッシュ` に部分一致して誤った語を返すことが見つかった（正解は `キャッシュフロー`）。
- 閾値を使わず上位3件を人に見せる場合のRuriの命中は、70mが19/22（0.86）、310mが22/22（1.00）。

## 読み取れること

1. 表記ゆれ・言い換えは、一致検索では拾えない（0/22）。Ruriは拾える。この課題セットでは、用語を『候補として並べる』用途で効果がある。
2. 弱いのは**閾値**。devの無関係課題の1つ（`サーバー室の鍵を総務に返却します。`）が、70mで0.849、310mで0.805という高い類似度を出し、閾値がそこまで押し上げられた。70mでは、この閾値が正しい候補の多くも切り捨てた。無関係課題が10件では、閾値が不安定。
3. 310mは70mより安定して高い。ただし取得物が大きい（310mの重みは約1.2GB、70mのsnapshotは約0.29GB）。実行環境の依存（torchなど）も約0.85GBと大きい。
4. 速度は問題になりにくい。40語の用語集で、1課題あたりの中央値は70mが約0.2秒、310mが約0.5秒（`ctr_search.ruri_search` は呼び出しごとにモデルを読み込むため、その時間を含む）。
5. 再現性: 同じ入力で順位は一致した（先頭10課題×2回）。

## 限界（この結果を採否の根拠にしすぎない）

- 課題セットも正解も、Skillの設計者と同じAIが作った。独立していない。用語集は架空の40語で、実際の用語の難しさや量を表していない。
- **データの改訂**: 1回目の実行で、課題IDの接頭辞の衝突と、言い換え課題が用語集の説明文に近すぎる問題が見つかり、結果を見たあとで言い換え課題を書き直した。採否基準は変えていないが、事後の修正である。1回目の出力は [ruri-adoption-bench-run1-invalid.json](evidence/ruri-adoption-bench-run1-invalid.json) に無効として残した。
- 書き直し後の言い換え課題でも、問い合わせの2-gramの約15%が正解の文書と重なる（表記ゆれは約12%）。文面の重なりの影響は残る。
- 閾値の決め方（devの無関係課題の最大値）は、この検証のために置いた単純な規則で、最適化していない。
- 件数が少なく、区間は広い。分野・文体・用語集の規模（実際は数百語以上）への一般化は示せない。
- 310mは利用者のHugging Faceキャッシュにあった既存の取得物を読み取りだけで使った（snapshot `18b60fb8…`）。70mはリビジョン `07a8b0ab…` を一時領域へ取得した。
