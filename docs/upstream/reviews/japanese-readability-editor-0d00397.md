## 確認した内容(基準との差分を実測)
- `tools/install.py`: 1行。引数の説明文の既定パスが `skill/` から `skills/` に変わっただけ
- `tools/package.py`: 5行。コメントと生成物の注記の、パスの表記が同じく `skill/` から `skills/` に変わっただけ
- 原因は、リポジトリ内のディレクトリ名 `skill/` → `skills/` の改名(上流の #66)。目的は、`gh skill` が名前だけで Skill を見つけること。処理の変更はない

## 照合(このプロジェクト)
`gh skill` の挙動を、v0.1.14 で実測した(gh 2.105.0、macOS、使い捨てのフォルダへ導入)。

| 操作 | 結果 |
|---|---|
| 名前だけで導入 | `no skills found`。gh が探すのは `skills/*/SKILL.md`、`*/SKILL.md` など。`skill/`(単数)は含まれない |
| SKILL.md のパスを指定して導入 | 入る。frontmatter に `metadata:`(`github-path` など)が足される |
| `gh skill update --dry-run` | 「Skipping … no skills found」と出して飛ばし、「All skills are up to date.」と表示する |

## 判断
- 採る: `docs/INSTALL.md` に、`gh skill` は対象外であることと、上の限界を短く書く。更新を確認できていないのに「最新」と読める表示は、利用者を誤らせるため
- 評価してから決める: `skill/` → `skills/` の改名。Skills CLI の既存の導入先、`release.yml`、テスト、文書、公開 URL に響く。利益が費用に見合うかを、Issue #65 で評価する
- 採らない: 評価の前の改名。`gh skill` を、Skills CLI と並ぶ正式な導入手段にすること(v0.1.14 で一本化した方針を保つ)
