# 判断の規則

## 基準の選び方

一律の権威順を使わない。今回の用途・対象に適用できる資料を選び、基準を「語・語義・分野・適用場面・資料の版と位置」の組で扱う。同じ語の複数の有効な定義は併存させる。

| 見たいこと | 見る資料 |
|---|---|
| 専門的な意味 | 適用される規格、原論文、製品・言語・APIの公式資料、手法の原典 |
| 責務・成果物・完了条件 | 当該案件の契約、仕様、成果物一覧、役割分担、正式な手順 |
| 社内慣用 | 組織・案件に限定した語義として残す。専門分野の定義を上書きしない |
| 個人の好み | 根拠付きの誤用とは別に保存する |

- 正式合意、草案、個人メモ、議事録の未決事項を区別する。更新・失効・矛盾を記録する。「最新だから優先」とは決めない。旧案件には旧版が適用される場合がある。
- 英語原文と日本語の訳・要約は別に保持する。訳で条件や断定の強さが変わっていないか確認する。未確認の訳を正式な日本語定義にしない。
- 未登録語は、原資料を調べた「今回の発言に限った暫定レビュー」にする。確認前に恒久ルールへ登録しない。
- 資料が読めない・適用条件が不明・資料間で競合する場合は、複数候補と確認点を示し、確定誤用にしない。
- 転載・複製は元資料との関係を残し、独立した裏付けの件数に数えない（`copy_of` を使う。`check refs` が `independent_source_count` を出す）。
- 検索は、用語・別名の一致（`search exact`）が基本。案件・版・時点で絞る。概念検索（Ruri）は候補を増やす任意の方式で、得点は正しさの確率ではない。

## 判定の4軸（一つの点数にまとめない）

1. 専門的適合: `conformant`（適合）/ `misuse_with_basis`（根拠付き誤用）/ `unknown`（不明）/ `out_of_scope`（対象外）
2. 意図の明確さ: `explicit` / `ambiguous`（解釈が分かれる）/ `insufficient_sources`（資料不足）
3. 業務上の前提: `agreed`（合意済み）/ `not_agreed`（未合意）/ `unverifiable`（確認不能）
4. 提案: `meaning_preserving_fix` / `needs_confirmation` / `preference`（好み）/ `no_change`

本人の意図は業務上の事実を証明しない。資料がないだけなら `unverifiable` で、`not_agreed` と断定しない。

## 意味保持

保護するのは確認済み事実・本人の意図・責務・条件。照合する観点: 数値と単位、条件と例外、否定、主体、言い切りの強さ、発話の働き（報告・依頼・予定・仮定）、責務・承認・完了状態。

- 「取りまとめます」→ 主担当としての責務が資料・本人の説明で確認済みなら明示してよい。最終承認権は、資料にない限り足さない。
- 「引き渡します。未リリースです」→ 未リリースだけで部分引渡しと断定しない。成果物が設計書一式か、サービス一式か、不明かで判断を変える。
- 誤用の訂正（例: 加速度の単位 m/s → m/s²）は、根拠が示す範囲だけ直す。`correction` に訂正対象・根拠・前後の意味差を書き、無関係な責務・完了状態を足さない（`unrelated_additions` は空）。原文との全文一致を合否にしない。

### 実際に起きた失敗（構造として覚える）

- **範囲の縮小・拡大をしない**: 資料の「成果物の作成」を「資料づくり」に狭めない。「設計書の提出」を「サービス一式の納品」に広げない。上位の語を下位の語にすり替えると、責務の範囲が変わる。
- **部分否定を全否定にしない**: 資料が「AだけではBにはならない」と言うとき、「Bは完了していない」と書き換えない。Bが済んだかどうかは、資料が言っていない。
- **修正案は短く**: 修正案は、原文の2倍程度までにする。担当範囲・条件・留保を一文に詰め込まず、確認が必要な点は「確認が必要な点」に分ける。口頭・チャット・表のセルに、そのまま貼れる長さにする。
- **正しい用法に付随する小さな気づきは、指摘にしない**: `conformant` の語について、「ほかの語も定義すると丁寧」といった補足は挙げない。直すと意味や責務が変わる点、本人の意図が定まらない点だけを挙げる。

## 相手・媒体への合わせ方

専門的意味と正式合意を固定し、説明量だけを変える（同僚: 短く／他職種・顧客: 用語の補足を付ける／口頭・チャット: 一文を短く）。丁寧さのために、未合意の約束や決定権を加えない。未解決の責務・完了条件にAIの推奨値を既定採用しない。

## 範囲の外

コード全体、計算、科学モデル全体の妥当性は保証しない。単位や記号の照合が合っても、モデル全体が正しいとは言わない。
