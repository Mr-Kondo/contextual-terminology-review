# 評価と週30分の運用

このSkillの検査（`tests/`）は動作確認であり、使用中に出す評価は人の採点の集計である。LLMだけで客観的な理解や正しさを証明しない。公開された開発・受入例の成績を、未使用評価や実務効果として扱わない。

## 指標（分子／分母）

分母0は「未評価」。件数・独立課題数・保留・欠測を併記する。分野・例の種類・利用環境別に出し、総合平均で隠さない。

| 指標 | 分子／分母 |
|---|---|
| 検索 hit@k | 正解根拠が上位kに入る課題／正解資料が存在する課題（`ctr_search.hit_at_k`） |
| 指摘の適合 | 正しい確定指摘／確定指摘 |
| 見落とし | 検出しなかった確定誤用／正解の確定誤用 |
| 有害な意味変更 | 責務・条件・概念を不適切に変えた案／人が検証した案 |
| 参照と引用 | 追跡できた判断／根拠表示が必要な判断、原文一致した引用／検査した引用 |
| 根拠の意味適合 | 判断を支える参照／人が検証した参照 |
| 保留・過剰修正 | 適切な保留／判断不能課題、不要な保留／判断可能課題、不要な指摘がある課題／修正不要課題 |
| 受け手の理解 | 意図と一致した必須項目／評価計画の必須項目（未回答を分母から除かない） |
| 本人の習得 | AIなしの後日・別課題で再発した機会／判断が必要だった機会 |

`ctr.py evaluate metrics` は、記録から出せるもの（引用不備、人が確認した不要な修正、意図の変化、受け手確認）を分子・分母・欠測・独立課題数つきで出す。利用総数が未知なら収集率は出さない。信頼区間（Wilson）は、分母が独立課題数と一致し十分な件数があるときだけ。根拠のない総合80点・90%などの合格線は置かない。

## 匿名二候補比較・理解問題

- `ctr.py blind prepare` は、読み手には左右の候補だけを渡し、方式名・版名・正解を含めない。割付と実際の配布物のハッシュは主催者側（organizer/）に保存する。
- `blind score` は、意味保持の合否を候補ごとに独立して数え、fail/unknown がある候補は採用候補にしない。選好は両候補が意味保持に合格した組だけで数える。読みやすさの評点で意味変更を相殺しない。
- `comprehension prepare` は、一人に同じ課題の一つの版だけを渡す（`comprehension check` で配布物を確認）。正解・根拠・確認者は主催者側。別の版を先に読んだ回答は除外して件数を示す。自由記述は人の採点と理由を保存する。AIなしの後日・別課題は別評価。
- organizer/ と評価用正解を、レビューを生成するAgentのセッションや読み取り可能な場所へ渡さない。フォルダ分離だけではアクセス隔離を達成したことにならない（`check isolation` は経路の重なりを見るだけで、`access_isolated: not_demonstrated` と出す）。

## 未使用評価

改善用と未使用評価用を分け、同じ案件・元発言の言い換えを両方に入れない。未使用例を改善に使ったら以後は未使用と数えない（`evaluate holdout --register`、`evaluate regression` が登録簿を更新する）。同一課題の反復は安定性評価として別集計する。

## 比較の枠

Skillなし／現行の推敲Skill（あれば）／根拠付きの本Skill／本Skill＋Ruri。固定資料・課題・採点条件を同じにし、提示量と検索条件の差を記録する。オンライン探索は別試験。環境・モデルごとに新しいセッションを使い、Skill・データ・索引・モデルの版と出力を保存する。

## 週30分

記録5分、根拠確認15分、比較5分、自力の言い直し・更新候補5分が初期案。日々の入力と初期設定もこの30分に数える（`feedback time`）。固定件数・全分野を強制しない。超えるときは確認数を減らして保留を残し、自動採用で埋めない。`check sample` は指摘なし例を含む確認候補を、基準とseedを記録して選ぶ（抽出されなかった例を正しいとみなさない）。協力者の時間は別に記録する。
